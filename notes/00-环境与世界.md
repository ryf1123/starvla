# 00 环境与世界：踩坑笔记

## 场景用 MjSpec 程序化搭，不写 XML

`mujoco.MjSpec.from_file(panda/scene.xml)` 之后可以往里加 body / geom / camera / site，再 `compile()`。
好处：随机化"桌上有什么"只是改 Python 参数；坏处：MjSpec 的 API 文档少，属性名要靠 `dir()` 试。

**腕部相机只能这么加**：`hand.xml` 里没有预留 site 和 camera，而 `<include>` 进来的 body 没法在 XML 里再往里塞子节点。
用 MjSpec 拿到 `spec.body("hand")` 再 `add_camera()` / `add_site()` 是唯一干净的办法。

## 相机朝向调了三次才对

MuJoCo 相机**沿自己的 −z 轴看**，+y 是画面上方。手掌坐标系的 +z 指向两指之间。
所以腕部相机要绕 x 转 180°：`quat = [0, 1, 0, 0]`。

- 第一次 `quat=[0,0,0,1]`（绕 z 转 180°）：相机朝手腕内部看，整个画面是一片灰白（手掌内壁）。
- 第二次 `[0, 0.966, 0.259, 0]`：能看到手指了但画面歪 30°。
- 第三次 `[0, 1, 0, 0]` + `pos=[0, -0.055, 0]`：两指分列画面左右，方块在中间——对了。

前视相机用 `mode=targetbody, targetbody=table` 自动瞄准桌子，只需要调 pos 和 fovy。
第一版 `pos=[1.35,0,0.85], fovy=45` 时方块在 128×128 里只有几个像素；
改成 `pos=[1.02,0,0.78], fovy=52` 后工作区铺满画面。**对 128×128 的视觉输入，这个差别是决定性的。**

## TCP 用手掌位姿加偏移，不用 site 也行

Franka 官方的 TCP 在手掌坐标系 +z 方向 0.1034 m 处（两指中心）。加了个 site 方便 `mj_jacSite` 直接取雅可比。

## 世界坐标 → 像素的投影公式

标注图要把三维坐标画到渲染图上，公式（相机看 −z）：

```
p_cam = R_camᵀ (p_world − t_cam)          # R_cam, t_cam 取自 data.cam_xmat / data.cam_xpos
f     = (H/2) / tan(fovy/2)
u     = W/2 + f · p_cam.x / (−p_cam.z)
v     = H/2 − f · p_cam.y / (−p_cam.z)
```

注意用的是 `data.cam_*` 而不是 `model.cam_*`——`targetbody` 模式下朝向是运行时算出来的。

## IK：30 次迭代不一定够

阻尼最小二乘，λ=0.15，`max_step=0.3 rad`。桌面工作区内典型残差 < 1 mm；
但把目标放到 (0.65, 0.2, 0.55) 这种接近臂展边缘的地方，30 次迭代后还有 11 mm。
控制环里每步只跑 12 次迭代——因为每步目标只移动 4 cm，上一步的解就是很好的初值，
**残差会在连续几步里自然收敛**。`info["ik_pos_err"] > 5 mm` 是"进了奇异位形"的报警信号。

## 位置控制器跟不满指令

一个控制步里指令末端走 42.4 mm，25 个物理子步后实际只走了 29.9 mm。
这不是 bug，是 PD 位置控制器的正常滞后。重要的是**专家和策略共享同一个滞后**：
专家用"指令位置"而不是"实际 TCP"算比例控制误差，否则会一直往前顶、越顶越远。

# 03 语言表示：什么信息保住了，什么信息被压掉了

指令「把**红色**方块放进**黄色**盘子」里，两个颜色词的**顺序**决定谁是被抓的、谁是目标。
在本项目升级后的任务里（盘子颜色从方块颜色里取），角色对调的两句话在同一个场景里
**都成立且结果不同**，所以语序是必需信息。

一个好的语言表示要同时满足两件事：

- **A. 角色对调的两句必须区分**（红→黄 vs 黄→红）
- **B. 同义改写的两句应该接近**（「把红色方块放进黄色盘子」vs「拿起红色的方块，放到黄色盘子里」）

## 实测：三种表示

| 表示 | 角色对调（越低越好） | 同义改写（越高越好） |
|---|---|---|
| 字符词袋 | **1.000** | 0.740 |
| 冻结句向量 bge-small-zh（CLS） | **0.998** | 0.946 |
| 冻结 token 特征的平均 | **0.996** | 0.930 |

图：`docs/figs/lang_repr.png`。

两个结论：

1. **任何形式的"池化成一个向量"都把角色信息压掉了**，包括专门训过中文的句向量模型。
   句向量模型是按"语义相似"训出来的，颜色对调在它眼里几乎就是同一句话。
2. **预训练确实带来措辞鲁棒性**：同义改写从 0.740 提到 0.946，极简说法从 0.629 提到 0.896。
   字符级词表连「拿」「起」「到」「里」这些字都没有，换个说法等于把指令删掉一半。

所以两者兼得的做法只有一个：**保留 token 序列，让一个可学的读出层自己去读**。
这正是真实 VLA 用 VLM 的 token 序列、而不是一个句子 embedding 的原因。

## 本项目的四种可选实现

| `model.lang_mode` | 是什么 | 预期 |
|---|---|---|
| `none` | 常数向量 | 只能瞎猜抓哪个 |
| `bow` | 字符嵌入求平均 | 角色不分 |
| `seq` | 字符 + 位置编码 + Transformer + **均值池化** | 看起来有序，实测退化成词袋 |
| `cls` | 同上但用可学的 [CLS] 读出，位置编码放大 | 基线（bc_v3 用的就是它） |
| `ppool` | 冻结 bge 句向量 + 线性投影 | 措辞鲁棒，角色不分 |
| `ptok` | 冻结 bge token 特征 + **可学注意力池化** | 两者兼得（待验证） |

`seq` 那一条是实测出来的：训好之后 ‖z(红→黄) − z(黄→红)‖ = 0.046，
而换一组颜色是 2.72——均值池化把顺序抹平了，位置编码的梯度信号又太弱
（训练前后 std 只从 0.020 长到 0.023）。

## 定性证据（bc_v3，`lang_mode=cls`）

`docs/figs/lang_swap.png`：**完全相同的初始场景**，只换指令，四条指令四种行为，
其中包含角色对调的组合，两次都做对了。定量结论等 `--suite lang` 和
`--suite pretrained_lang` 跑完。

## 闭环消融结果（16000 步，40 局，同一套种子）

| lang_mode | 训练 L1 | 验证 L1 | 关键点 std | max_p | 闭环成功率 | 抓错方块 |
|---|---|---|---|---|---|---|
| seq | 0.0747 | 0.0908 | 0.271 | 0.174 | **80.0%** | 0 |
| cls（基线） | 0.0804 | 0.0925 | — | — | **72.5%** | 0 |
| **bow** | 0.0976 | 0.1138 | 0.248 | 0.417 | **12.5%** | **12** |

三个读法：

1. **词袋直接崩掉**，12/40 局抓错方块。两句角色对调的指令字符集完全相同，
   词袋给出同一个向量，策略只能猜。这是本项目最干净的一个因果证据。
2. **验证 L1 只差 25%，成功率差 6.4 倍。** 而且 bow 的视觉分支完全健康
   （kp_std 0.248、max_p 0.417，比 seq 还尖），坏掉的只有语言接地这一块。
   选错方块只影响轨迹的一部分动作维度，loss 上几乎看不出来。
3. **之前"seq 会退化成词袋"的说法要更正**：那是在旧任务上测的。
   旧任务里颜色集合就足以定位目标，语序没有信息，模型学到的最小充分表示自然是词袋。
   换成新任务（语序必需）之后，同样的 seq 结构拿到 80%。
   准确的说法是：**均值池化会不会抹掉顺序，取决于任务逼不逼它保留顺序。**
   而且 seq 池化的是 Transformer 的**上下文化输出**（每个位置已经吸收全局信息），
   和池化原始嵌入的 bow 完全是两回事。

## lang_none：0%，而且不是"三选一猜错"那种

完全拿不到指令的那组 40 局一局没成（抓错方块 15 / 没抓起来 14 / 没进盘子 11）。

直觉上它该有 1/3 蒙对方块 × 1/2 蒙对盘子 ≈ 17%。实际是 0，因为
**回归头会输出所有可能目标的平均动作**——三个方块在三个不同位置，
平均出来的动作对任何一个目标都不成立，手停在几个方块中间来回蹭。
这是单峰回归头碰上多峰目标分布的典型失效。

顺带说明了动作表示那一环为什么值得做：**离散 token 和扩散头天然能表达多峰分布**，
理论上不会退化成平均值（会挑一个目标做，虽然可能挑错）。`--suite heads` 会验证。

## 语言这一环的完整结论

| lang_mode | 能表达什么 | 成功率 | 抓错方块 |
|---|---|---|---|
| seq | 顺序（上下文化后池化） | **80.0%** | 0 |
| cls（基线） | 顺序（[CLS] 读出） | **72.5%** | 0 |
| bow | 只有颜色集合 | **12.5%** | 12 |
| none | 什么都没有 | **0.0%** | 15 |

**能不能表达顺序，是 80% 和 12.5% 的分界线。**

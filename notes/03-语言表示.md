# 03 语言表示：什么信息保住了，什么信息被压掉了

指令「把**红色**方块放进**黄色**盘子」里，两个颜色词的**顺序**决定谁是被抓的、谁是目标。
在本项目升级后的任务里（盘子颜色从方块颜色里取），角色对调的两句话在同一个场景里
**都成立且结果不同**，所以语序是必需信息。

一个好的语言表示要同时满足两件事：

- **A. 角色对调的两句必须区分**（红→黄 vs 黄→红）
- **B. 同义改写的两句应该接近**（「把红色方块放进黄色盘子」vs「拿起红色的方块，放到黄色盘子里」）

## 实测：三种表示

| 表示 | 角色对调（越低越好） | 同义改写（越高越好） |
|---|---|---|
| 字符词袋 | **1.000** | 0.740 |
| 冻结句向量 bge-small-zh（CLS） | **0.998** | 0.946 |
| 冻结 token 特征的平均 | **0.996** | 0.930 |

图：`docs/figs/lang_repr.png`。

两个结论：

1. **任何形式的"池化成一个向量"都把角色信息压掉了**，包括专门训过中文的句向量模型。
   句向量模型是按"语义相似"训出来的，颜色对调在它眼里几乎就是同一句话。
2. **预训练确实带来措辞鲁棒性**：同义改写从 0.740 提到 0.946，极简说法从 0.629 提到 0.896。
   字符级词表连「拿」「起」「到」「里」这些字都没有，换个说法等于把指令删掉一半。

所以两者兼得的做法只有一个：**保留 token 序列，让一个可学的读出层自己去读**。
这正是真实 VLA 用 VLM 的 token 序列、而不是一个句子 embedding 的原因。

## 本项目的四种可选实现

| `model.lang_mode` | 是什么 | 预期 |
|---|---|---|
| `none` | 常数向量 | 只能瞎猜抓哪个 |
| `bow` | 字符嵌入求平均 | 角色不分 |
| `seq` | 字符 + 位置编码 + Transformer + **均值池化** | 看起来有序，实测退化成词袋 |
| `cls` | 同上但用可学的 [CLS] 读出，位置编码放大 | 基线（bc_v3 用的就是它） |
| `ppool` | 冻结 bge 句向量 + 线性投影 | 措辞鲁棒，角色不分 |
| `ptok` | 冻结 bge token 特征 + **可学注意力池化** | 两者兼得（待验证） |

`seq` 那一条是实测出来的：训好之后 ‖z(红→黄) − z(黄→红)‖ = 0.046，
而换一组颜色是 2.72——均值池化把顺序抹平了，位置编码的梯度信号又太弱
（训练前后 std 只从 0.020 长到 0.023）。

## 定性证据（bc_v3，`lang_mode=cls`）

`docs/figs/lang_swap.png`：**完全相同的初始场景**，只换指令，四条指令四种行为，
其中包含角色对调的组合，两次都做对了。定量结论等 `--suite lang` 和
`--suite pretrained_lang` 跑完。

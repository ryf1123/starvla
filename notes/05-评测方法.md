# 05 闭环评测的方法学：怎样才算"A 比 B 好"

这个项目里所有结论都靠闭环成功率。所以必须先搞清楚：**这个数字本身有多大噪声。**

## 三个不确定性来源

### 1. 采样噪声（主要来源）

40 局的成功率，95% Wilson 区间大约 ±14 个百分点：

| 观测 | 95% 区间 | 宽度 |
|---|---|---|
| 24/40 = 60% | 45%–74% | 29% |
| 30/40 = 75% | 60%–86% | 26% |
| 37/50 = 74% | 60%–84% | 24% |

**两组差 10 个百分点，在 40 局下说明不了任何问题。** 要下结论要么差距远大于区间，要么加局数。
`scripts/summary.py` 的表里每一行都带区间，就是为了不把噪声当结论。

### 2. 混沌（次要，5%）

同一个策略、同一个种子、同一套权重，只要 GPU 上的执行历史不同
（比如"每局新建环境"而不是"复用同一个环境"），就有约 **5% 的局会翻转结果**：

```
顺序跑        成功率 72.5%
每局新建环境   成功率 72.5%
逐局结果翻转   2/40 = 5%     （seed 1004: off_plate → success，seed 1038: 反过来）
```

原因：MPS 上浮点运算结果依赖执行历史（差异在 1e-7 量级），经过 140 步闭环 + 接触动力学被放大。
初始状态是完全相同的（指令、TCP、方块和盘子的位置逐位相同，验证过）。

好消息是**翻转会互相抵消，总成功率纹丝不动**。所以：
- 聚合指标可信；
- 单局的"为什么这一局失败"要小心，它可能只是站在边界上。

### 3. 训练随机性（未测）

不同随机种子重训同一配置的方差还没测。理论上这项最大，
因为 8000 步 vs 16000 步同配置能差 7 倍（见 `notes/02`）。
真要下强结论，应该每个配置训 2–3 个种子——但一次训练 40 分钟，暂时负担不起。
**目前所有消融结论都只有单个训练种子，读的时候要记住这一点。**

## 因此本项目的规矩

1. 每个配置 ≥ 40 局闭环，同一套随机种子（配对比较）。
2. 表里必带 95% 区间；差距小于区间宽度的，只说"看不出差别"。
3. 每个套件的基线臂共享同一次训练（`runs/bc_v3`），减少一个变量。
4. 所有消融跑到收敛（16000 步）；8000 步的对照测的是收敛速度，不是能力。
5. 失败必须分类（抓错方块 / 没抓起来 / 没进盘子），因为**同样的成功率可以来自完全不同的病因**。

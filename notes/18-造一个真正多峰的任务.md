# 18 造一个真正多峰的任务：先量下限，再写预测

## 起因：姊妹项目已经踩过同一个坑

`notes/17` 的结论是"回归 93.8%、离散 46%、扩散 3.8%"。
姊妹项目 seamless-interaction 在完全不同的任务（语音驱动手势）上得到了**同一个形状的结论**：
确定性回归 98.5% 完胜 flow matching 64.2%。

但他们往下多做了一步，而这一步是我该学的：**先量数据自己有多随机。**

> 一个模型不可能比数据本身的条件随机性做得更准。

他们量出来数据的条件变异只有 3.37 cm，而回归的误差是 3.86 cm——**已经贴着噪声底**。
于是结论从"生成式不行"改成了"**我造的任务不是多对多的，所以生成式没有用武之地**"，
接着他们改数据、重跑，排序真的翻转了。

## 第一步：量 StarVLA 数据的条件变异

做法（`scripts/diagnose_multimodality.py`）：正常跑若干局，在沿途的每个状态上**冻结环境**，
用 K=16 个不同的随机种子问专家 16 次，得到"同一个观测下专家动作的真实分布"，然后算两条下限：

```
均值式模型的下限   E|a_k − mean_k a|     ← 回归的最优解是条件均值
采样式模型的下限   E|a_k − a_k'|         ← 采样式模型的最优解是从条件分布里采一个
```

**这两条必须分开算**，因为两类模型的最优解不一样——拿同一个 L1 去比它们是不公平的。

现有任务（指令指定了盘子）：

| | 均值式下限 | 采样式下限 | 实测 | 离自己的下限 |
|---|---|---|---|---|
| 回归 | **0.0286** | — | 0.0843 | **2.95×** |
| 扩散 | — | **0.0387** | 0.1396 | **3.61×** |

**和姊妹项目不一样**：他们的回归贴着下限（1.04×），我们的差了 2.95 倍。
所以在 StarVLA 上，"回归赢"**不是**因为它已经做到极限——
这里的瓶颈是感知和容量，不是数据的随机性。

但条件分布确实近乎单峰：变异 0.03 只是采集时注入的动作噪声（σ=0.05），
相对动作量程 [-1,1] 微不足道。**给定指令，该做什么没有任何歧义。**
所以"多峰表示"在这个任务上本来就无从发挥——这一点和姊妹项目一致。

## 第二步：造一个真正多峰的任务

`any_plate`：指令**不说放进哪个盘子**——「把红色方块放进盘子」——
专家每局**随机挑一个**，放进任意盘子都算成功。

一个必须守住的细节：**这个选择必须和场景无关**。
如果专家总挑离方块近的那个，策略就能从图像里推出来，条件分布又变回单峰了。
实测：选中"更近的那个盘子"的比例 **48.0%**，两个盘子被选中 195 : 205——干净。

重新量条件变异（这次连"这局要放进哪个盘子"这个**观测里看不见的隐变量**也一起重采）：

| 阶段 | 单峰任务 均值式 / 采样式 | **多峰任务** 均值式 / 采样式 |
|---|---|---|
| 0 悬停对准 | 0.026 / 0.035 | 0.026 / 0.035 |
| 1 下降 | 0.029 / 0.039 | 0.030 / 0.040 |
| 2 闭合夹爪 | 0.031 / 0.042 | 0.031 / 0.042 |
| 3 抬起 | 0.029 / 0.039 | 0.028 / 0.039 |
| **4 平移到盘子上方** | 0.028 / 0.037 | **0.195 / 0.207** |
| **5 下降放置** | 0.029 / 0.039 | **0.175 / 0.188** |
| 6 松开撤离 | 0.030 / 0.040 | 0.105 / 0.116 |
| 全部 | 0.029 / 0.039 | 0.082 / 0.093 |

**分岔点被精确定位在"抓起来之后"**：抓取阶段（0–3）一模一样，
平移阶段（4）的条件变异涨了 **7 倍**。这正是任务该有的样子——
抓哪个方块是确定的，放进哪个盘子是自由的。

### 一个顺带发现的多峰性指标

「采样式下限 / 均值式下限」这个比值本身就是分布形状的探针：

- 单峰（高斯型）：两个独立样本的距离 ≈ √2 × 到均值的距离 → 比值 **≈1.35–1.41**
- 双峰（两个模式各占一半）：两者都等于半模式间距 → 比值 **→1.0**

实测：

| | 采样式 / 均值式 | 读法 |
|---|---|---|
| 单峰任务（全程） | 0.0386 / 0.0285 = **1.35** | 接近 √2，典型的单峰高斯 |
| 多峰任务（全程） | 0.0932 / 0.0823 = **1.13** | 被前四个单峰阶段稀释了 |
| **多峰任务，只看分岔点（阶段 4）** | 0.207 / 0.195 = **1.06** | **双峰的特征** |

**不用画图就能判断一份数据是不是多峰的。**
（注意要分阶段看：整段平均会被那些本来就单峰的阶段稀释——
全程 1.13 看起来不显眼，分岔点上的 1.06 才是真正的信号。）

## 第三步：预测（写在跑之前）

同一套骨干、同一份 `any_plate` 数据、同样 16000 步：

1. **回归会明显掉下来。**它的最优解是条件均值——在分岔点上就是"两个盘子的中间"。
   预计成功率从 93.8% 掉到 **50–70%**，且失败集中在 **`dropped`/`off_plate`**
   （方块被放到两个盘子中间的空地上），而不是抓取类失败（`pushed`/`no_grasp`）。
   —— 这是最关键的一条：**失败构成必须在放置类上变化，抓取类不变**，
   因为抓取阶段的条件变异根本没变。

2. **离散 + argmax 应该反而占优。**argmax 是一个"承诺"操作：它挑概率最高的那个格子，
   而不是把两个模式平均掉。`notes/17` 里 argmax 的硬跳是缺点，
   在这里同一个性质变成优点。预计它和回归的差距会**缩小**，甚至反超。

3. **离散 + 期望解码应该退回到和回归一样。**期望 = 平均 = 走中间。
   这一条是对 `notes/17` 那个机制解释的**交叉检验**：
   如果期望解码在这里也掉到回归的水平，说明"argmax 会承诺、期望会平均"这个理解是对的。

4. **扩散大概率还是最差。**它的问题（采样质量本身就差 1.6 倍）与多峰无关，
   多峰只是让它少了一个劣势，没有给它新的优势。
   如果它反超回归，说明我在 `notes/17` 里低估了"能采样"这件事的价值。

**可能推翻我的结果**：如果回归在多峰任务上几乎不掉（>85%），
说明策略从别的地方（比如场景里某个我没想到的线索）推出了盘子选择，
那这个任务设计就没成功，得重新检查。

## 补：一个先跑出来的结果，已经在修正我的直觉

在 `any_plate` 之前先跑了一个更粗暴的多峰版本——**把指令整个拿掉**
（`mm_none_regress`：同样的最佳配置，只是 `lang_mode=none`），80 局：

```
成功率 6.2% (5/80)
失败归因：wrong_cube=33  no_grasp=20  dropped=8  off_plate=7  pushed=7
```

**`wrong_cube` 占了 41%**——也就是说，拿不到指令的回归策略**并没有瘫在中间输出"平均动作"，
它果断地挑了一个方块去抓，只是经常挑错。**

这和我预测里"回归会走两个模式的中间"那句话不完全一致。更准确的说法是：

> 回归输出的是**条件均值**没错，但"条件均值"在动作空间里长什么样，取决于**观测能不能把模式区分开**。
> 如果网络能从图像里找到一个确定性的 tie-break 规则（比如"总去离夹爪最近的那个"），
> 那它就会**承诺**，而不是平均——因为对训练数据来说，"总选最近的"比"总走中间"的 L1 更低。

所以 `any_plate` 那组要多量一个东西：**回归到底是走中间，还是学了个 tie-break 规则？**
可测的量：

- 方块最终落点离**两个盘子连线中点**的距离 → 走中间的话这个数会很小；
- 落点更靠近哪个盘子，和"哪个盘子离方块更近 / 更靠画面左边"的相关性 → 有 tie-break 规则的话会显著。

这两个数会把"平均"和"承诺"彻底分开。**这一条写在结果出来之前。**

### 追问：它承诺的依据是什么？四个假设全部落空

既然 `mm_none_regress` 已经训好了，就直接查它挑方块的依据（50 局，其中 36 局动了某个方块）：

| 它挑的方块 = … | 一致比例 | 随机基线 |
|---|---|---|
| 这一局真正的目标（它看不到） | 36.1% | 33.3% |
| 离夹爪起点最近的 | 25.0% | 33.3% |
| 画面最左边的 | 22.2% | 33.3% |
| 离机器人最近的 | 13.9% | 33.3% |

再查颜色偏好（40 局，30 局动了方块）：绿 32.3%、蓝 23.3%、黄 21.9%、红 22.2%，
随机基线 33.3%——**也没有偏好**。

**四个假设全部落空。**"和真正的目标一致 36.1% ≈ 随机"这一条同时确认了
它确实拿不到指令信息（这是个好的 sanity check）。

所以准确的说法是：**它确实在承诺（每局果断地去抓某一个），但依据不是任何一个
简单可解释的规则。**最可能的解释是网络把输入空间做了一个**任意的划分**——
对每张具体的图像，确定性网络必须输出一个具体动作，
而 L1 目标在模式相距很远时并不会真的把它推到"中间"（那里的 L1 也很大），
于是它退化成按图像里某些特异特征硬分。

这条修正了教科书式的说法。**"回归会收敛到条件均值"这句话，
描述的是无限容量 + 完美优化下的极限，不是有限网络在有限数据上的实际行为。**
`any_plate` 那组会在一个**只有两个模式、而且两个模式都合法**的干净设定上再问一次
——那里"走中间"是可测的（落点离两盘中点的距离），不像"抓哪个方块"这么难界定。

# 结果（一）：回归头，56.2%——预测对了，但机制不是我说的那个

`any_regress`：同一套最佳配置，只把数据换成 `place_any`，16000 步，80 局。

| | 单峰任务 | **多峰任务** |
|---|---|---|
| 成功率 | 93.8% | **56.2%** |
| 抓错方块 | 0 | 0 |
| 没碰到 | 2 | 3 |
| 推走了 | 2 | 3 |
| 掉了 | 1 | 4 |
| **没进盘子** | **0** | **25** |

## 预测 1：对了，而且对得很干净

预测写的是"掉到 50–70%，且失败集中在放置类而不是抓取类"。
实测 **56.2%**，35 个失败里 **29 个是放置类**（没进盘子 25 + 掉了 4），抓取类只有 6 个。

**失败正好搬到了条件变异变大的那几个阶段**：
抓取阶段（0–3）的条件变异两个任务完全一样 → 抓取类失败几乎不变（4 → 6）；
放置阶段（4–5）涨了 7 倍 → 放置类失败从 1 涨到 29。
**这是"数据的条件随机性决定误差下限"这句话最直接的一次验证。**

## 预测里错的部分：它没有"走中间"

我写的机制是"回归的最优解是条件均值，在分岔点上就是两个盘子的中间"。
`scripts/diagnose_commit.py` 直接量了（40 局）：

| | 成功率 | 落点进了某个盘子 | **落点在"中间"** | 离最近盘子 | 离两盘中点 | 选了更近的盘 | 选了画面左盘 |
|---|---|---|---|---|---|---|---|
| 脚本专家 | 100% | 100% | 0% | **6 mm** | 138 mm | 42.5% | 50.0% |
| `any_regress` | 57.5% | **62.5%** | **15.0%** | **41 mm** | 137 mm | 60.0% | 62.5% |

- **只有 15% 的局落在"中间"**，而且落点离两盘中点的距离（137 mm）**和专家一模一样**（138 mm）——
  它并没有往中间跑。
- 真正变化的是**精度**：落点离最近盘子的中位距离从 **6 mm 掉到 41 mm**。
  盘子半径 65 mm，判定阈值是 50 mm——**41 mm 的中位数意味着有一大半局擦着边缘**，
  于是 25 局判成"没进盘子"。
- 两个 tie-break 倾向都不显著：选更近的盘 24/40（p=0.27）、选画面左盘 25/40（p=0.15）。

**修正后的机制**：多峰不是让回归头"瘫在中间"，而是让它在分岔点上**变得不确定，
从而丢失精度**。它仍然承诺去某个盘子，只是抖着过去、落点散开 7 倍。

这和 `mm_none_regress` 那边看到的是同一件事：
**"回归收敛到条件均值"描述的是无限容量 + 完美优化下的极限，
不是有限网络在有限数据上的实际行为。**实际行为是"承诺，但承诺得不干脆"。

# 结果（二）：离散头——预测 2 错了，预测 3 对得漂亮

| | 总成功率 | 抓起来过 | **抓起来之后放进去** |
|---|---|---|---|
| 多峰 回归 | **56.2%** | 74/80 | 60.8% [49%, 71%] |
| 多峰 离散 argmax | 25.0% | 35/80 | 57.1% [41%, 72%] |
| 多峰 离散 期望解码 | 20.0% | **49/80** | **32.7%** [21%, 47%] |

## 预测 2（离散会反超）：**错了**

离散头 25.0%，远低于回归的 56.2%。原因一分解就清楚：
**它的缺陷在抓取阶段，而多峰只发生在放置阶段。**
80 局里它只抓起来 35 次（回归 74 次）——**根本走不到分岔点，"能承诺"这个优势没机会兑现。**

但把放置阶段单独拿出来看，方向是对的：

| 抓起来之后放进去 | 单峰任务 | 多峰任务 | 掉了多少 |
|---|---|---|---|
| 回归 | **98.7%** | 60.8% | **−37.9** |
| 离散 argmax | 82.4% | 57.1% | −25.2 |

单峰任务上回归的放置明显更好（98.7% vs 82.4%），
到了多峰任务上**两者变得没有差别**（60.8% vs 57.1%，区间大幅重叠）。
也就是说多峰**确实**更伤回归——只是伤得不够多，不足以翻盘。

## 预测 3（期望解码会退回到"走中间"）：**对了，而且是全项目最干净的一次**

同一个模型、同一份权重、同一批种子，**只换解码规则**：

| | 抓起来过 | 抓起来之后放进去 |
|---|---|---|
| **单峰任务** argmax → 期望 | 34 → **41** | 82.4% → 90.2%（p=0.50，看不出差别） |
| **多峰任务** argmax → 期望 | 35 → **49** | 57.1% → **32.7%**（Fisher **p=0.043**） |

**同一个开关，在两个阶段上符号相反：**

- **抓取阶段（两个任务里都是单峰）**：期望解码**总是有帮助**（34→41、35→49）。
  它消掉了 argmax 的抖动——和 `notes/17` 量到的"2.6% 的步跳变 >0.5"完全对得上。
- **放置阶段**：任务单峰时期望解码无害（甚至略好）；
  **任务多峰时它把两个合法模式平均掉，方块落在两个盘子中间，`off_plate` 从 11 局暴涨到 26 局。**

这是本项目最强的一个双向解离（double dissociation）：
**一个设计选择的好坏，不取决于这个设计本身，而取决于数据的一个可测量的性质。**
而这个性质（条件变异、分岔点在哪）是可以**在训练之前就量出来的**。

（caveat：两组的"抓起来过"子集不同，Fisher 检验在这里是近似的；
但两个方向相反的效应量都不小，且和事先写下的机制预测一致。）

## 预测 4（扩散还是最差）：**对了，但没什么信息量**

`any_diffusion`：**0.0%**（0/80）。失败构成 `no_grasp=51`、`wrong_cube=18`——
**它的失败几乎全在抓取阶段**，而抓取阶段在两个任务里都是单峰的。
也就是说多峰与否对它根本不构成变量：它在到达分岔点之前就已经废了。

结合 `notes/17` 的诊断（采样后的开环误差就是回归的 1.6 倍），
这一版扩散头的问题是**实现/预算**，不是表示能力。
"扩散头适合多峰"这个命题在本项目里**没有被检验到**——
要检验它，得先有一个在单峰任务上就能work的扩散头。
（`head_diffusion_long`，同结构训 32000 步，在队列里。）

## 四条预测的总账

| | 预测 | 结果 |
|---|---|---|
| 1 | 回归掉到 50–70%，失败集中在放置类 | ✅ 56.2%，放置类占 29/35 |
| 1b | 机制是"走中间" | ❌ 只有 15% 走中间；真实机制是**精度丢失**（落点 6 mm → 41 mm） |
| 2 | 离散 argmax 会缩小差距甚至反超 | ❌ 25.0%，因为它卡在抓取阶段；但**放置阶段**方向确实对（−25.2 vs 回归 −37.9） |
| 3 | 期望解码会退回到"走中间" | ✅ 放置成功率 57.1% → 32.7%，Fisher p=0.043 |
| 4 | 扩散还是最差 | ✅ 0.0%，但失败在抓取阶段，与多峰无关 |

**两条对、两条错、一条方向对量级错。**
最有价值的是错的那两条：如果不写下来，
事后很容易把"离散 25%"解释成"果然多峰表示没用"，而不去做阶段分解——
而阶段分解才是这一组真正的结论。

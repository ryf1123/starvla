# 21 更正：验证损失并不是"不能用"，是在关键的那一段里不能用

## 我一直在说的那句话

"**训练 loss 不是指标**"——这句话在本项目的笔记、README 和飞书文档里出现了至少五次，
每次都配一两个例子（8000 步 vs 16000 步 val L1 好 16% 而成功率好 7 倍；
回归头和离散头 val L1 几乎一样而闭环差 59 个百分点）。

**这个说法太粗了。**把 `runs/` 下**所有** 33 个有闭环评测的实验拿出来一起看：

```
全部 33 个实验：            Spearman ρ = −0.82
```

**−0.82 是很强的相关。**验证损失确实能预测闭环成功率——
val L1 从 0.084 到 0.19 这个范围里，它几乎单调地对应成功率从 94% 到 1%。

## 真正的问题在哪

把范围缩到"都学会了"的那一小段：

| 范围 | 实验数 | Spearman ρ | 成功率跨度 |
|---|---|---|---|
| 全部 | 33 | **−0.82** | 0%–94% |
| val L1 ∈ [0.080, 0.102] | 21 | −0.61 | 24%–94% |
| **val L1 ∈ [0.080, 0.095]** | **14** | **−0.21** | **35%–94%** |

在最后这一段里，验证损失只差 0.015（相对差 18%），**成功率却横跨 35% 到 94%**，
而秩相关掉到 −0.21——基本没有分辨力。

具体几个：

```
bc_v5_hist        val L1 0.0843   成功率 93.8%
head_discrete_h   val L1 0.0868   成功率 35.0%     ← 差 0.0025，闭环差 59 个百分点
rel_cls_hist      val L1 0.0874   成功率 47.5%
lang_seq          val L1 0.0908   成功率 80.0%
vis_relu16        val L1 0.0949   成功率 87.5%     ← val L1 最差的一个，闭环第二好
```

## 正确的说法

> **验证损失能把"完全没学会"和"学会了"分开，但在"都学会了"的那一段里几乎没有分辨力。
> 而我们做的每一个选择——选动作头、选语言编码器、选视觉配置、决定要不要早停——
> 恰恰全都落在那一段里。**

所以"val loss 不是指标"这个结论**在实践中仍然成立**（因为实践中我们只在那一段里做选择），
但它成立的**理由**和我原来写的不一样：不是"验证损失和成功率无关"，
而是"**在我们关心的那个窄带里，它的信噪比不够**"。

## 为什么值得单独记一页

这是本项目第七次"我先有了一个解释，然后被自己的数据推翻"，
但前六次推翻的是**关于系统的判断**，这一次推翻的是**关于方法的判断**——
而方法上的错误说法会传播到之后的每一个决定。

顺带一个操作层面的结论：**如果两个配置的 val L1 差 20% 以上，可以先信它做粗筛；
差 5% 以内就必须跑闭环。**本项目的窄带（0.084–0.095）正好是后者。

复现：`python -m scripts.explain_valloss`（读 `runs/` 下所有 eval.json，无需重训）。
